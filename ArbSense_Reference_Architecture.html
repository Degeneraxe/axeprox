1. Purpose and scope

This document defines the ArbSense architecture as five functional layers (public market feeds, order book normalization and dual storage, spread detection and dynamic cost hurdles, deep learning duration forecasting, and execution simulation/paper trading) plus supporting cross-cutting planes. Every element traces to concrete engineering specifications and acceptance tests.

Goal. To construct an autonomous, high-throughput market microstructure engine that ingests concurrent Level 2 order books from premier cryptocurrency exchanges (Binance, Coinbase, Kraken); synchronizes arrival clocks via SNTP (RFC 4330) to eliminate host skew; predicts the temporal persistence duration and net viability of price dislocations using a PyTorch Multi-Head LSTM; and executes paper trades with depth-walking VWAP slippage while enforcing strict fee-hurdle gatekeepers.

Scope. Cryptocurrency spot markets (BTC/USDT, ETH/USDT, ADA/USDT, XRP/USDT, SOL/USDT). Mode: Paper trading and simulation only; no live money, zero private API keys.

4. Layer 2: Storage Selection (Decision Record)

Option Strengths Weaknesses Verdict
SQLite WAL Engine (Primary) Zero-dependency; embedded local file; single-digit ms writes; 64MB cache; perfectly suited for local paper trading and academic defense demo. Not distributed across multiple network servers without shared network filesystem. Recommended (Deployed)
TimescaleDB / PostgreSQL Native SQL hypertables; automated chunk partitioning; multi-node distributed scaling. Requires running external Docker container / daemon process. Alternative (Production)
MongoDB / InfluxDB Schemaless document store; fast simple appends. Weak relational joins between spread events and executed trades; poor SQL tooling. Not recommended
